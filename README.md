# DC MEP -- Residential MEP Design Proposal

This repository contains the interactive residential MEP design proposal
prepared by **DC MEP**. It presents the design workflow, indicative
timelines, scope-related deliverables, and proposal information in a
browser-friendly format.

## View the proposal

After GitHub Pages is enabled, the proposal will be available at:

`https://YOUR-GITHUB-USERNAME.github.io/dc-mep-design-proposal/`

Replace `YOUR-GITHUB-USERNAME` with the GitHub username that owns the
repository.

## Proposal workflow

The interactive workflow is organised into five stages:

1.  **Initial site meeting** -- A meeting involving the client,
    architect, and DC MEP team to understand the project brief,
    architectural information, site conditions, and service
    requirements.
2.  **Concept design** -- Indicative timeline of **5--6 working days**
    for projects approximately **3,000--8,000 sq. ft.**
3.  **Revision 1** -- Indicative timeline of **2--3 working days** for
    minor revisions.
4.  **Revision 2** -- Indicative timeline of **4--5 working days** for
    major revisions.
5.  **Final handover and review** -- Review and handover of the MEP
    design deliverables included in the agreed project scope.

Additional site visits can be arranged according to the client's
requirements and project needs. They are not fixed at every workflow
stage.

Timelines are indicative and depend on receiving the required project
information and consolidated feedback.

## Handover deliverables

Depending on the agreed scope, the handover may include:

-   Complete MEP drawings for the agreed scope
-   Editable DWG files
-   PDF drawing set
-   Applicable load sheets
-   Relevant schedules, calculations, and BOQ documents where included
    in the agreed scope

## Publish with GitHub Pages

1.  Create a **public** GitHub repository named
    `dc-mep-design-proposal`.
2.  Upload the proposal HTML file and rename it to `index.html`.
3.  Upload this `README.md` file to the repository root.
4.  Open the repository's **Settings**.
5.  Select **Pages** from the sidebar.
6.  Under **Build and deployment**, choose **Deploy from a branch**.
7.  Select branch **main** and folder **/(root)**, then click **Save**.
8.  Wait for GitHub Pages to finish publishing. The website link will
    appear in the Pages section.

The proposal's main page must be named `index.html` and placed in the
repository root for the expected URL to work.

## Updating the proposal

To publish an updated version, replace the existing `index.html` (and
any related assets, if applicable) with the updated files, commit the
changes to the `main` branch, and allow GitHub Pages to redeploy.

## Important

A public GitHub Pages site can be viewed by anyone who has the URL, and
it may be discoverable. Do not publish confidential client information,
private contact details, or commercially sensitive project data in this
public repository.
